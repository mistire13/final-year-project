- Explicit opt-in: `ENABLE_DEMO_PAYMENTS=true` **and** `NODE_ENV=development`; default example setting is false. Production cannot enable simulation through this flag.
- Separate `/payments/demo` operation; real initiation and unverified webhooks remain unavailable.
- Server derives order total and identity, enforces parent ownership/daycare/current order state, locks the order/payment and returns an existing demo result on retry. Only the first transition adds the payment audit event.
- Checkout, result, parent receipt, admin list and status editor identify simulation. Demo amounts are excluded from monetary revenue totals.

- Existing cancelled order **#44** appeared cancelled to the parent, offered no payment action and stated no collection was due. Receipts now distinguish preparation, readiness, collection and cancellation.
