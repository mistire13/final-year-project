# Ankelba release audit — 11 November 2026

Scope: current local workspace, excluding biometric pickup. No application code or operational settings were changed. Database test writes used disposable local databases. The release inventory read the configured local database without changing it.

## Unfinished features and release tasks

- **Applied bank refunds and partial or combined payments.** Audited full cash refunds exist. Confirmed but unapplied transfers can be reconciled. Applied bank transfers do not have an equivalent refund recording workflow, and receipt verification expects one order total or one invoice's full remaining balance. Decide which of these cases the pilot daycares need, then design the ledger and operator process around that scope.
- **Weekly and daily tuition.** Monthly automation is implemented. [Weekly and daily rules are deferred](../DAYCARE_RECEIPTS_AND_LIFECYCLE_DISCUSSION_PLAN.md#6-daily-weekly-and-monthly-care-fees) until daycares confirm booked versus attended days, absence/holiday treatment, and overlapping billing rules.
- **Live acceptance and production configuration.** Approve real package prices and receiving accounts, prove one genuine designated transfer per enabled provider, and verify the expiry/renewal journey. The local inventory found all six prices populated and no pending migrations, but SaaS name-and-amount diagnostic matching is still on locally. The loose development setting accepted a synthetic wrong receiving account; strict matching kept the same receipt pending. Production ignores the diagnostic bypass. Local SMTP and the frontend origin are not configured, and email reminders are off. Choose the staging/production host, verify HTTPS, run the workers under supervision, and prove an offsite backup restore. See the [release runbook](../PLUS_RELEASE_RUNBOOK.md).
- **Device, accessibility and usability acceptance.** Run the latest parent and caregiver builds on physical Android and iOS, and all four role journeys in the browser. Focus on session recovery, narrow screens, text scaling, caregiver reporting, shop and tuition retries, expiry, keyboard navigation, and fallback when a provider is unavailable. The current audit used automated tests and a web export. It did not include live transfers, physical-device checks, or a full interactive browser rerun.
- **Policy decisions.** Agree retention and deletion rules for sensitive child, health, message, and AI data before a real pilot. Optional activity photos and device push notifications should remain separate scope decisions. In-app notifications already exist.
- **Safe automated checks.** The default [backend `npm test`](../../backend/package.json#L14) runs a legacy script that [can reset an existing account's password](../../backend/master_audit.js#L393) in the configured database. It was not run. Make the disposable suites the default, restore the missing ESLint configuration, and require backend tests, frontend tests and TypeScript checks before merging.

The suites covered payments and receipt reuse, tenant isolation, role authorization, care reporting, communications, scheduling, analytics, billing and subscription activation.
- The full frontend test run reported four failures, all in the subscription screens. TypeScript failed on `ScheduledPackageSummary`. The production web export completed.
- Targeted probes separately reproduced the manual CBE review exception, production password reset `503`, the native staff URL fallback, a four-character paid signup password, and subscription screenshot OCR `503`.
